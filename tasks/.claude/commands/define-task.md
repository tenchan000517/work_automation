# /define-task - タスク要件定義

タスクIDを受け取り、要件定義を深掘りするスキルです。

## 使い方

```
/define-task T-042
```

## 実行手順

1. 引数からタスクIDを取得（例: T-042）
2. ユーザーから提供されたタスク情報を確認
3. 以下の4項目について深掘りする：

### 深掘り項目

**KGI（本当のゴール）**
- 依頼者が本当に望んでいることは何か
- 表面的な指示の裏にある目的を言語化する

**手離れの定義**
- 何がどうなっていれば、このタスクから手を離せるか
- 成果物の完成だけでなく「誰に渡すか」「どこに格納するか」「報告は必要か」まで含める

**スコープ**
- やること: 明確に含まれる作業を列挙
- やらないこと: 含まれない・やるべきでない作業を明示（暗黙の期待を先回りして潰す）

**リスク・確認事項**
- 期限に対して作業量は妥当か
- 不足している情報・素材はないか
- 依頼者に確認すべき曖昧な点はないか

## 出力フォーマット

深掘り結果を以下のMarkdownで `/mnt/c/work-manual/tasks/requirements/` に保存：

```markdown
# 要件定義: {タスクID} {タスク名}

## KGI（本当のゴール）
{記述}

## 手離れの定義
{記述}

## スコープ
### やること
- {項目}

### やらないこと
- {項目}

## 依頼者に確認すべきこと
- [ ] {質問}

## リスク・注意点
- {項目}

---
定義日: {YYYY-MM-DD}
```

## 注意事項

- ユーザーとの対話を通じて深掘りする。一方的に決めず、質問→回答→整理のサイクルを回す
- 「いい感じに」「前と同じ」などの曖昧表現は必ず具体化する
- 完了後、GASスプレッドシートの要件定義列（M列）への反映はユーザーに案内する
