# タスク管理システム フローテストシナリオ集

> **目的:** 実際の業務を想定し、タスク発生→完了までの全パターンをGASで実行・検証する
> **実行者:** シート上で手動実行（ダイアログ操作）
> **前提:** テンプレート初期設定済み、担当者3名登録済み

---

## 登場人物

| 名前 | 役割 | 性格・特徴 |
|------|------|-----------|
| 河合さん | 担当者 | メイン作業者。真面目だが、複数タスクを抱えると優先順位に迷う |
| 川崎さん | 担当者 | 撮影・外出が多い。LINE WORKSでの報連相がメイン |
| 青柳さん | 管理者 | CC（チーフコーディネーター）。全工程を把握したい。承認権限を持つ |

---

## 月曜日: 週の始まり

---

### シナリオ1: 朝会のLINE WORKSログから一括タスク抽出

**状況:** 月曜朝、先週金曜〜土日のLINE WORKSグループチャットが溜まっている。雑談・業務連絡・依頼が混在。

**社員の悩み:** 「週末のメッセージが30件以上ある。どれがタスクでどれが雑談か、読み返すのが面倒...」

**GAS操作:**
1. メニュー → 📋 タスク管理 → ➕ タスク登録 → 💬 ワークス一括
2. 以下のテキストを貼り付けて「AI解析する」

**貼り付けるテキスト:**
```
青柳: お疲れ様です。来週の中部建設の撮影日程、先方に確認してもらえますか？
河合: 了解です。月曜に連絡します。
川崎: 撮影機材の予備バッテリー、充電しておきます。
青柳: ありがとう。あと、共立工業のヒアリングシート、Part②がまだ空欄多いので埋めてください。期限は水曜まで。
河合: 承知しました。火曜のMTG後に入力します。
川崎: 週末にスカイリフォームの写真整理しました。Google Driveにアップ済みです。
青柳: 確認しました。写真いい感じですね！
河合: ところで、三河精密のHP、トップページのキャッチコピー案を3つほど出してもらえますか？
川崎: 了解です。木曜までに出します。
青柳: 月次FBのスライド、先月分のテンプレを使って今月分を作っておいてください。金曜の会議で使います。
河合: 了解です。
川崎: あ、そういえば昨日のラーメン屋おいしかったです笑
青柳: 笑。それ気になる。今度連れてって。
```

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | AI解析が完了する | ダイアログが画面2（候補一覧）に遷移 |
| 2 | タスク候補の件数 | 4〜5件が検出される |
| 3 | 雑談がスキップされる | 「ラーメン屋」「写真いい感じ」等がスキップ一覧に |
| 4 | 担当者が正しく割り当て | 河合→中部建設連絡/ヒアリング/スライド、川崎→キャッチコピー |
| 5 | 期限が検出される | 共立工業→水曜、キャッチコピー→木曜、スライド→金曜 |
| 6 | 確信度が適切 | 明確な依頼は「高」、「いい感じ」は曖昧表現として検出 |
| 7 | 要件確認画面で編集可能 | 担当者・期限・完了条件を変更できる |
| 8 | 登録完了後にClaude Codeボタンが表示 | 各タスクの「🤖 Claude Code」ボタンが押せる |

**起こりうる問題:**
- 「写真整理しました」が完了報告なのに新規タスクとして検出される
- 「いい感じ」がambiguous_expressionsとして検出されるが、これは褒め言葉であってタスクではない
- 「月曜に連絡します」の「月曜」が正しい日付に変換されるか

### シナリオ2: 1件だけ急ぎの指示（ワークスピンポイント）

**状況:** 朝会後、青柳さんから河合さんに個別メッセージ。「今日中に対応して」という急ぎの案件。

**社員の悩み:** 「一括でやったばかりなのに、また別の依頼が来た。こっちは急ぎだから先に登録したい」

**GAS操作:**
1. メニュー → 📋 タスク管理 → ➕ タスク登録 → 📌 ワークスピンポイント
2. 以下を貼り付け

**貼り付けるテキスト:**
```
青柳: 河合さん、スカイリフォームのLP、クライアントから修正依頼が来ました。ファーストビューの画像差し替えと、CTAボタンの色変更です。今日中にお願いします。修正内容はメールで転送しました。
```

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 1件のタスクとして検出 | 画像差し替え+CTA色変更が1つのタスクにまとまる |
| 2 | 担当者 | 河合さん |
| 3 | 期限 | 本日（今日の日付） |
| 4 | 確信度 | 高 |
| 5 | 完了条件がAI生成される | 「画像差し替えとCTAボタン色変更が完了し、クライアントに報告」等 |

**起こりうる問題:**
- 「画像差し替え」と「CTA色変更」が別タスクとして分離してしまう
- 「今日中」が正しく本日の日付に変換されない
- 「メールで転送しました」が別タスクとして検出される

### シナリオ3: 担当者設定の初期セットアップ

**状況:** 管理者の青柳さんが初めてシステムを使う。まず担当者を登録する。

**管理者の悩み:** 「カレンダーIDって何？メールアドレスと何が違うの？」

**GAS操作:**
1. メニュー → ⚙️ 管理者メニュー → 👤 担当者設定
2. 3名を登録:

| 名前 | メール | カレンダーID | 役割 |
|------|--------|-------------|------|
| 河合 | kawai@example.com | kawai@example.com | 担当者 |
| 川崎 | kawasaki@example.com | kawasaki@example.com | 担当者 |
| 青柳 | aoyagi@example.com | aoyagi@example.com | 管理者 |

3. 「保存」を押す

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 保存成功メッセージ | 「保存しました」が表示 |
| 2 | 設定シートに反映 | A2:D4に3名分のデータ |
| 3 | 空行を入れても無視される | 名前が空の行は保存されない |
| 4 | 担当者追加ボタンが機能 | 「＋ 担当者を追加」で行が増える |

**起こりうる問題:**
- カレンダーIDを空にした場合、カレンダー登録がスキップされるか
- 同じ名前を2行登録した場合の挙動
- 役割を「担当者」から「管理者」に変更したとき、承認権限が即座に反映されるか

## 火曜日: 作業開始・進行管理

---

### シナリオ4: NOTTA議事録からタスク抽出

**状況:** 火曜の定例MTG。NOTTAで文字起こしした議事録からタスクを抽出。

**社員の悩み:** 「議事録が長すぎて、誰が何を約束したか追いきれない。30分の会議で文字起こし5000文字...」

**GAS操作:**
1. メニュー → 📋 タスク管理 → ➕ タスク登録 → 📝 NOTTA
2. 以下を貼り付け

**貼り付けるテキスト:**
```
青柳: では定例MTGを始めます。まず先週の進捗確認から。河合さん、中部建設はどうですか？
河合: トップページとアバウトページは完成しました。サービスページは今週中に仕上げます。
青柳: 了解。写真素材は足りてますか？
河合: 社長の写真がまだです。川崎さん、来週撮影でしたっけ？
川崎: はい、来週火曜に撮影予定です。ただ、撮影場所の下見がまだなので、今週金曜に行きます。
青柳: 下見は一人で大丈夫？
川崎: はい、大丈夫です。下見の結果はLINE WORKSで共有します。
青柳: お願いします。次、共立工業の件。河合さん、構成案の状況は？
河合: ヒアリング内容をまとめて、今週木曜までに構成案のドラフトを出します。
青柳: 構成案はClaude Codeで作る？
河合: はい、JSON出力してClaude Codeに渡します。
青柳: いいですね。あとは月次報告。川崎さん、先月の撮影実績をまとめておいてください。水曜までにスプレッドシートに記入。
川崎: 了解です。
青柳: それと、来月のスケジュール調整。全員、来月の空き日程をカレンダーに入れておいてください。
河合: はい。
川崎: 了解です。
青柳: では以上です。お疲れ様でした。
```

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 検出タスク数 | 5〜6件 |
| 2 | 完了タスクがスキップされる | 「トップ・アバウトページ完成」はタスクでなく報告 |
| 3 | 各タスクの担当者が正しい | 河合→サービスページ/構成案、川崎→下見/撮影実績/スケジュール |
| 4 | 期限の検出 | サービスページ→今週中、構成案→木曜、撮影実績→水曜 |
| 5 | 「全員」タスクの扱い | スケジュール登録が全員分に分割されるか、1タスクとして出るか |

**起こりうる問題:**
- 「来週火曜に撮影予定です」が新規タスクとして誤検出される（既に予定済み）
- 「全員、来月の空き日程を〜」が1タスクか3タスクか曖昧
- 「Claude Codeで作る」が技術的な会話でタスクではないのに検出される可能性
- NOTTAの文字起こし特有の誤字（「下見」→「したみ」等）で解析精度が落ちる

### シナリオ5: タスク一覧の確認と作業開始

**状況:** 火曜午後。河合さんが自分のタスクを確認し、優先順位をつけて作業を開始する。

**社員の悩み:** 「タスクが8個もある。どれから手をつければいいんだろう。期限が近いのは分かるけど、重要度が高いものとどっちを優先すべき？」

**GAS操作:**
1. メニュー → 📋 タスク管理 → 📊 タスク一覧
2. 担当者フィルタで「河合」を選択
3. 各タスクをクリックして詳細を確認
4. スカイリフォームLP修正（本日期限）のタスクを展開
5. 作業完了後、「📝 完了報告」ボタンを押す
6. コメント: 「画像差し替え・CTA色変更完了。テスト環境で確認済み」

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 担当者フィルタが機能する | 河合のタスクのみ表示 |
| 2 | 期限超過が赤表示 | 超過タスクに🔴アイコン |
| 3 | 本日期限が黄表示 | 本日のタスクに🟡アイコン |
| 4 | サマリーバーの集計 | 「合計:X件 🔴超過X 🟡本日X」が正確 |
| 5 | 完了報告後にステータスが変わる | 「完了報告済み」に更新 |
| 6 | コメントが記録される | シートのI列に記録 |
| 7 | タスク一覧が自動リフレッシュ | 完了報告済みタスクが🔵表示に |

**起こりうる問題:**
- 期限の日付フォーマットが「2026-03-12」と「2026/3/12」で混在していると比較が狂う
- 完了報告ボタンを押した後、ダイアログが閉じてしまい結果が見えない
- 「未着手」のタスクにも完了報告ボタンが出る（進行中にせず直接報告）

### シナリオ6: 自由記述でのタスク登録

**状況:** 河合さんが自分でやるべきことを思い出した。口頭で誰かに言われたわけではなく、自分の備忘録。

**社員の悩み:** 「AIに出す必要ないかもだけど、タスク管理に入れておかないと忘れる。でも自分メモをAIに解析させるのは大げさかな...」

**GAS操作:**
1. メニュー → 📋 タスク管理 → ➕ タスク登録 → ✍️ 自由記述
2. 以下を入力

**貼り付けるテキスト:**
```
・中部建設HPのfavicon設定（忘れてた）
・共立工業の写真、リサイズして圧縮する（PageSpeed対策）
・来週のMTG資料に進捗グラフを入れる
```

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 3件のタスクとして検出 | 箇条書きが各タスクに |
| 2 | 担当者 | 全て未特定（自分メモなので） |
| 3 | 期限 | 全て未設定 |
| 4 | 要件確認で担当者を自分に設定可能 | ドロップダウンから選択 |

**起こりうる問題:**
- 箇条書きの「・」が解析に影響する可能性
- 「忘れてた」「PageSpeed対策」のような注釈がタスク名に含まれてしまう
- 担当者が「未特定」のまま登録すると、一覧で「未割当」グループに入る

## 水曜日: 中間チェック・問題発生

---

### シナリオ7: 管理者が承認・差し戻しを行う

**状況:** 青柳さんが完了報告されたタスクを確認。1件は承認、1件は差し戻し。

**管理者の悩み:** 「完了報告が来たけど、本当に大丈夫？確認する時間がない。でも見ないで承認するのも怖い...差し戻すと担当者のモチベーション下がりそう」

**GAS操作:**
1. メニュー → ⚙️ 管理者メニュー → ✅ 完了承認・差し戻し
2. スカイリフォームLP修正 → 「✅ 承認」→ 承認者名「青柳」
3. 撮影実績まとめ → 「↩️ 差し戻し」→ 理由「数字の集計が合っていません。先月の撮影は8件ではなく10件です。再確認お願いします」→ 差し戻し者名「青柳」

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 管理者ビューで承認・差し戻しボタンが表示 | 「完了報告済み」のタスクにのみ表示 |
| 2 | 承認後のステータス | 「完了」に変更 |
| 3 | 承認メモ | J列に「青柳 承認 2026/03/12 HH:mm」形式 |
| 4 | 差し戻し後のステータス | 「差し戻し」に変更 |
| 5 | 差し戻し理由 | J列に「差し戻し（青柳）：数字の集計が合っていません...」 |
| 6 | メール通知 | 承認→川崎にメール、差し戻し→川崎にメール |
| 7 | 一覧が更新される | 承認タスクは非表示、差し戻しは表示継続 |

**起こりうる問題:**
- 承認者名の入力がpromptダイアログなので、間違えて空で送信してしまう
- 差し戻し理由が長すぎるとシートの列幅に収まらない
- メール通知が飛ばない（メールアドレスが未設定の場合）
- 管理者以外が管理者メニューを開けてしまう（権限制御がない）

### シナリオ8: 差し戻されたタスクへの対応

**状況:** 川崎さんが差し戻し通知を受け取る。修正して再提出する。

**社員の悩み:** 「差し戻されるとちょっと凹む...でも理由が明確だから直しやすい。ただ、差し戻しのタスクってどこから再提出するんだっけ？」

**GAS操作:**
1. メニュー → 📋 タスク管理 → 📊 タスク一覧
2. 差し戻されたタスクを展開 → 差し戻し理由を確認
3. 修正作業を実施
4. 「📝 完了報告」ボタンを押す
5. コメント: 「撮影件数を10件に修正しました。集計表も更新済み」

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | 差し戻しタスクに完了報告ボタンが表示される | 差し戻し状態でもボタンあり |
| 2 | 再完了報告でステータスが「完了報告済み」に戻る | B列更新 |
| 3 | 新しいコメントが記録される | I列に新しいコメント |
| 4 | 前回の差し戻し理由が残っている | J列の内容が上書きされないか要確認 |

**起こりうる問題:**
- 差し戻し→進行中→完了報告済みの状態遷移が正しいか（直接完了報告済みに飛べる？）
- 2回目の完了報告コメントが1回目のコメントを上書きしてしまう
- 差し戻し回数が多いと、担当者が「何回直しても通らない」とフラストレーション

**コミュニケーション課題:**
- 差し戻し理由がシステム上にしか残らず、口頭フォローがない
- 差し戻し回数の可視化がないため、繰り返し差し戻しに気づきにくい

---

### シナリオ9: ディスカッションモードでの口頭依頼登録

**状況:** 水曜の昼休み明け、青柳さんが河合さんに廊下で「あの件、よろしく」と口頭で依頼。河合さんはその場でメモできなかった。

**社員の悩み:** 「『あの件って何だっけ...』と思いながらも、後から聞き返すのが恥ずかしい。覚えてる範囲でタスク化しておこう」

**GAS操作:**
1. メニュー → 📋 タスク管理 → ➕ タスク登録 → 🤝 ディスカッション
2. 「何を頼まれましたか？」→ 「共立工業のLP用バナーのデザイン案を3パターン作る」
3. 「誰から？」→ 「青柳」を選択
4. 確認事項の質問が表示される → わかる範囲で回答:
   - 「サイズや仕様の指定は？」→ 「横1200px、ファーストビュー用」
   - 「納期は？」→ 「来週月曜」
   - 「参考イメージは？」→ 「（空欄）」
5. 「AI解析する」を押す

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | デザイン系パターンが検出される | 質問がデザイン系に特化 |
| 2 | 質問の表示 | サイズ、色、参考イメージ等の質問が出る |
| 3 | 空欄の質問がスキップされる | 未回答でもAI解析可能 |
| 4 | タスクの完了条件がAI生成される | 「3パターンのバナーデザイン案を提出」等 |
| 5 | 不足情報がwarningsに出る | 「参考イメージが未指定」等 |

**起こりうる問題:**
- ディスカッションモードのAI解析が通常より時間がかかる
- 「バナー」→ デザイン系パターンのキーワードマッチが機能するか
- 口頭依頼なので抜け漏れが多い → AIの追加質問が重要

**コミュニケーション課題:**
- 口頭依頼は記録が残らない。言った言わない問題の元
- 「あの件」が何を指すか、後から確認できる仕組みがない
- 依頼者（青柳さん）がタスク登録を確認する手段がない

## 木曜日: 期限間近・リマインド

### シナリオ10: リマインドメールの確認

**状況:** 朝9:00にリマインドメールが届く。期限が今日・超過のタスクが通知される。

**社員の悩み:** 「メールが多すぎて埋もれる。リマインドが来てるのに気づかなかった。というか、リマインドの頻度が多すぎてオオカミ少年になってる」

**GAS操作:**（自動トリガーなので手動確認）
1. メニュー → ⚙️ 管理者メニュー → ⏰ リマインド設定 → 時間を確認
2. トリガーが正しく設定されているか確認（GASエディタ → トリガー）

**検証ポイント:**

### シナリオ16: 曖昧な指示ばかりのログ

**状況:** 指示が曖昧で、何をすればいいか分からないメッセージ群。

**社員の悩み:** 「『いい感じにして』『うまくやっておいて』って言われても...具体的に何をすればいいの？」

**貼り付けるテキスト:**
```

青柳: うーん、前に話したやつ。見た目をもうちょっとかっこよく

```

**検証ポイント:**

| # | 確認項目 | 期待値 |
|---|---------|--------|
| 1 | ambiguous_expressionsが検出される | 「いい感じ」「あれ」「先週言ったやつ」 |
