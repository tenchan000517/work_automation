# タスク管理システム 要件定義

## 背景・課題

### 事例から見えた問題の連鎖

```
① 会議でタスク発生 → 各自メモ → 共有されない → 漏れる
   ↓ 対策：スプレッドシート導入
② スプレッドシートに入力されない → 漏れる
   ↓ 対策：LINE WORKS導入
③ LINE WORKSで共有しても期限守られない → 遅延常態化
```

### 根本原因

| # | 原因 | 現象 |
|---|------|------|
| 1 | タスク発生の瞬間に捕まえていない | 会議後に「各自メモ」→ 登録されない |
| 2 | 入力する動機・強制力がない | 入れなくても困らない |
| 3 | 遅れを検知・対処する仕組みがない | 遅れても問題視されない |
| 4 | 要件定義が不十分 | 成果物がズレる（情報伝達のGAP） |

---

## 設計方針

### ヒューマンコスト最小化

```
人がやるのは：
  ・テキストを貼る
  ・✅ / ⬜ で選ぶ
  ・質問に答える
  ・「登録」を押す

AIがやるのは：
  ・テキストからタスク候補を抽出
  ・不明点を検出して質問
  ・回答を要件として整理
  ・完了時に元の要件と照合
```

### 不具合耐性

```
スプレッドシートが「正」のデータ
  → 自動化（リマインド等）が壊れてもタスク管理自体は影響ゼロ
  → GASはメンテナンスが容易、権限者なら誰でも修正可能
```

### AIの役割

```
✗ タスクかどうか判断する
○ タスクの可能性があるものは全部出す + 確信度を付ける
○ 曖昧な表現を検出して具体化を促す
○ 要件定義が完了するまでアシストする
○ スコープ（やること / やらないこと）を明確にする
```

## 入力モード（5種類）

| モード | 入力 | AIの動き |
|--------|------|---------|
| NOTTA | 会議文字起こし全文 | 会話から全タスクを自動抽出 |
| 自由記述 | 自分で書いた内容 | 5W1H不足チェック + 整理 |
| ワークス一括 | 会話ログ全体 | 全タスク候補を抽出 |
| ワークスピンポイント | 1メッセージだけ | そのメッセージからタスク抽出 + 不足チェック |
| ディスカッション | 「こういう依頼を受けた」 | 受けた側を支援。必要情報を洗い出す |

### ディスカッションモード詳細

受けた側が「要件定義」をするためのモード。
タスクの種類ごとに「聞くべきこと」のパターンをプロンプトに持たせる。

```
担当者：「バナー作成を頼まれました」
  ↓
AI：「以下を確認しましたか？」
  □ サイズ・フォーマットは？
  □ 使用用途は？
  □ 素材は提供される？
  □ 参考イメージは共有された？
  □ 確認フローは？（誰がOK出す？）
```

## 共通フロー

```
STEP 1：モード選択 + テキスト貼り付け
          ↓
STEP 2：AI解析 → タスク候補を一覧表示（確信度付き）
          ↓
STEP 3：✅ タスク化する / ⬜ スキップ を選択
          ↓
STEP 4：✅にしたものの不明点をAIが質問 → 回答入力
          ↓
STEP 5：要件確定 → 登録（スプレッドシート + カレンダー）
          ↓
STEP 6：Claude Codeで作業開始（任意）
```

✅ task-002 【確信度：低】名古屋北高校 取材成果のSNS発信

   担当：未特定 ｜ 期限：未設定

## 技術構成

```
GAS（Google Apps Script）
  ├── AI呼び出し（Gemini API）
  ├── スプレッドシート読み書き
  ├── Googleカレンダー連携（期限 → イベント登録 + リマインド）
  ├── メール送信（リマインド通知）
  ├── UIダイアログ（タスク入力・確認・登録）
  └── 時限トリガー（毎朝リマインド、週次サマリー）

連携できないもの：
  ❌ LINE WORKS（直接連携不可）
  → カレンダー通知 + メール通知でカバー
```

### GAS処理フロー

```
1回目のAI呼び出し：テキスト → タスク候補抽出 + 確信度 + 不明点検出
        ↓
   ダイアログで ✅/⬜ 選択 + 質問回答
        ↓
2回目のAI呼び出し：元テキスト + 回答 → 要件として整理
        ↓
   確認画面「これで登録しますか？」
        ↓
   登録 → スプレッドシート + カレンダー
```

## リマインド設計

### 毎朝トリガー（例：9:00）

```
GASがスプレッドシートを走査：
  → 期限が「今日」のタスク → メール通知（当日リマインド）
  → 期限が「明日」のタスク → メール通知（前日リマインド）
  → 期限を過ぎているタスク → メール通知（遅延アラート）
```

### 週次サマリー（例：月曜 9:00）

```
全未完了タスクの一覧をメールで送信
  → 遅延タスク数
  → 今週期限のタスク
  → 担当者別タスク数
```

## プロンプト（タスク抽出用）

```
あなたはタスク管理アシスタントです。

【役割】
テキストを受け取り、タスク候補を抽出・整理します。
あなたはタスクかどうかを「判断」しません。可能性があるものは全て抽出し、確信度を付けてください。
最終的にタスク化するかどうかは人が決めます。

【タスク候補の検出基準】
以下のいずれかに該当するものをタスク候補として抽出：
- 「〜お願い」「〜やっておいて」「〜しておいて」「〜頼める？」等の依頼表現
- 「〜担当で」「〜さんに」＋ 具体的な作業
- 明確な作業指示（「〜を作成」「〜を送付」「〜を確認」）
- 期限付きの依頼
- 報告の中に含まれる次のアクション（確信度：低として抽出）

以下はタスク候補として抽出しない：
- 雑談・感想・お祝い・リアクション
- 純粋な情報共有で次のアクションが一切示唆されないもの

【確信度の基準】
- 高：明確な依頼・指示がある（「〜お願い」「〜してください」）
- 中：作業が示唆されているが明確な指示ではない（「〜のイメージ」「〜する感じ」）
- 低：報告や会話から推測されるタスク（明確な指示なし）

【各タスクについて以下を整理】
1. 担当者（不明なら「未特定」）
2. 内容（具体的に何をするか）
3. 期限（具体的な日付。不明なら「未設定」）
4. 完了条件（何がどうなっていれば完了か）
5. やること / やらないこと
6. 必要な情報・素材
7. 状態（未着手 / 進行中 / 完了済み）
8. 確信度（高 / 中 / 低）

【曖昧表現の検出】
以下のような表現を検出し、具体化を求める質問を生成：
- 程度が不明：「いい感じ」「もうちょっと」「シンプルに」
- 参照が不明：「前と同じ」「いつもの」「あれ」「これ」
- 期限が不明：「なるべく早く」「急ぎで」「そのうち」「手空いたら」
- 範囲が不明：「〜とか」「〜など」「〜的な」
- 暗黙の前提：「当然〜も」「ついでに〜も」

【実現可能性の確認】
- 期限に対して作業量が多すぎないか
- 必要な素材・情報が不足していないか
- 他のタスクへの依存関係がないか

【出力形式】
JSON形式で出力。

{
  "tasks": [
    {
      "id": "task-001",
      "confidence": "高 | 中 | 低",
      "assignee": "担当者名 or 未特定",
      "title": "タスクの要約（20字以内）",
      "detail": "具体的な作業内容",
      "deadline": "YYYY-MM-DD or 未設定",
      "done_criteria": "完了条件",
      "scope_in": "やること",
      "scope_out": "やらないこと（推測含む）",
      "required_info": ["必要な情報・素材"],
      "status": "未着手 | 進行中 | 完了済み",
      "warnings": ["不明点や懸念事項"],
      "ambiguous_expressions": [
        {
          "original": "元の表現",
          "question": "具体化するための質問"
        }
      ]
    }
  ],
  "skipped_messages": [
    {
      "speaker": "発言者",
      "content_summary": "内容の要約",
      "reason": "スキップ理由"
    }
  ]
}
```

## 要件定義アシスト用プロンプト（STEP 4用）

```
あなたは要件定義アシスタントです。

以下のタスクについて、ユーザーの回答を受け取り、要件として整理してください。

【整理の原則】
- AIがテキストから読み取れた情報は自動で埋める
- 足りない部分だけ質問する（全部聞かない）
- 選択肢を出して答えやすくする
- 曖昧な表現は具体的な表現に変換する

【チェック観点】
□ 担当者が明確か
□ 期限が具体的な日付か（「来週中」→ NG、「3/21」→ OK）
□ 成果物が具体的か
□ 完了条件があるか（どこに納品？誰が確認？）
□ 「やること」が明記されているか
□ 「やらないこと」が明記されているか
□ 曖昧な表現が残っていないか

【出力形式】
全項目が埋まったら、確定用のJSON形式で出力。
不足がある場合は、質問リストを出力。
```

## ディスカッションモード用パターン（順次拡張）

タスクの種類に応じた「聞くべきこと」のテンプレート。

### 汎用（全タスク共通）

```
□ 目的・背景は？（なぜこれをやるのか）
□ 期限は？
□ 成果物は何？（ファイル？連絡？作業完了？）
□ 完了の確認者は誰？
□ 他に関連するタスクや依存関係は？
```

### デザイン・制作系

```
□ サイズ・フォーマットは？
□ 使用用途は？（SNS？サイト？印刷？）
□ 素材は提供される？自分で用意？
□ ブランドガイドラインはある？
□ 参考イメージは？
□ テキスト（コピー）は誰が書く？
```

### 資料・ドキュメント系

```
□ 目的・用途は？（社内？クライアント提出？）
□ 対象者は？（誰が読む？）
□ ページ数・分量の目安は？
□ テンプレートはある？
□ 元データ・素材はある？
```

### クライアント対応系

```
□ クライアント名は？
□ 対応内容は？（修正？確認？連絡？）
□ クライアントの温度感は？（急ぎ？通常？）
□ 窓口担当は誰？
□ 過去の経緯で注意すべきことは？
```

### 営業・外部連絡系

```
□ 相手先は？（企業名・担当者名）
□ 連絡手段は？（メール？電話？訪問？）
□ 伝える内容は？
□ 事前に準備する資料は？
□ 返答の期限は？
```

## Claude Code連携

タスクが確定した後、「Claude Codeで作業開始」を選択すると：
- 要件がClaude Code向けのプロンプトとして整形される
- コピーしてClaude Codeに貼り付け → 作業開始
