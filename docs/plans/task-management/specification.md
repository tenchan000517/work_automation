## スプレッドシート構成

### シート1：タスク一覧

これが全データの「正」。

| 列 | ヘッダー | 入力方法 | 例 |
|----|---------|---------|-----|
| A | ID | 自動 | T-001 |
| B | 状態 | ドロップダウン | 未着手 / 進行中 / 完了報告済み / 完了 / 差し戻し / 保留 |
| C | 担当者 | ドロップダウン | 河合 |
| D | タスク名 | AI生成→手動修正可 | コベルク提案資料修正 |
| E | 期限 | 日付 | 2026-03-20 |
| F | 完了条件 | AI生成→手動修正可 | 決裁取得 |
| G | 登録日 | 自動 | 2026-03-11 |
| H | 入力モード | 自動 | ワークス一括 |
| I | 完了報告コメント | 完了報告時に入力 | 両方発注済み。搬入は3/19 |
| J | 承認者 / 差し戻し理由 | 管理者が操作時に自動 | 笠本 承認 / 差し戻し：確認書を添付 |
| K | 備考 | 自由入力 | |

条件付き書式：
- 状態「完了」→ 行をグレーアウト
- 状態「完了報告済み」→ B列を青背景（管理者の確認待ち）
- 状態「差し戻し」→ B列をオレンジ背景
- 期限が今日以前 & 未完了 → 期限セルを赤背景
- 期限が明日 → 期限セルを黄背景

### シート2：設定

**GASにハードコードする値はゼロ。** 全て設定シートから読み取る。

#### エリア1：担当者設定（A〜E列）

| 列 | ヘッダー | 内容 | 例 |
|----|---------|------|-----|
| A | 担当者名 | 自由入力。増減可能 | 河合 |
| B | メールアドレス | リマインド送信先 | kawai@example.com |
| C | カレンダーID | Googleカレンダー連携用（任意） | kawai@example.com |
| D | 役割 | 管理者 / 担当者 | 担当者 |

- 担当者の追加・削除はここの行を増減するだけ
- ダイアログのドロップダウンはこのリストから自動生成

#### エリア2：システム設定（G〜H列）

| 行 | G列（設定名） | H列（設定値） | 説明 |
|----|-------------|-------------|------|
| 2 | AIモデル | gemini-3.1-pro-preview | AI呼び出し時のモデル |
| 3 | リマインド時間1 | 09:00 | 1回目のリマインド送信時刻 |
| 4 | リマインド時間2 | （空欄） | 2回目（空欄なら1回のみ） |
| 5 | リマインド時間3 | （空欄） | 3回目（空欄なら無し） |
| 6 | カレンダーリマインド1 | 前日 09:00 | カレンダー通知タイミング1 |
| 7 | カレンダーリマインド2 | 当日 09:00 | カレンダー通知タイミング2 |
| 8 | 棚卸し曜日 | 月曜 | 週次棚卸しサマリーの送信曜日 |
| 9 | 棚卸し時間 | 08:30 | 棚卸しサマリーの送信時刻 |

- リマインドを1日3回にしたければ時間2・3を埋める
- リマインドを朝だけにしたければ時間1だけ埋める
- 棚卸しを金曜にしたければ「金曜」に変えるだけ
- **全てスプレッドシートの値を変えるだけで反映される**

### シート3：ログ（非表示でもOK）

AIへの入力テキスト原文と、AI出力の全文を保存。
トラブル時に「何を入れて何が出たか」を追跡できる。

| 列 | ヘッダー |
|----|---------|
| A | 日時 |
| B | 入力モード |
| C | 入力テキスト（原文） |
| D | AI出力（JSON） |
| E | 登録されたタスクID |

```javascript
function onOpen() {
  const ui = SpreadsheetApp.getUi();

  // メニュー1：全員が使う
  const taskMenu = ui.createMenu('📋 タスク管理');

  // タスク登録サブメニュー
  const registerSub = ui.createMenu('➕ タスク登録')
    .addItem('💬 ワークス一括', 'showInputDialog_WorksBulk')
    .addItem('📌 ワークスピンポイント', 'showInputDialog_WorksPin')
    .addItem('📝 NOTTA', 'showInputDialog_Notta')
    .addItem('✍️ 自由記述', 'showInputDialog_FreeText')

    .addSubMenu(registerSub)

    .addItem('📝 完了報告', 'showCompletionReportDialog')
    .addSeparator()
    .addItem('❓ 使い方', 'showHelpDialog')

  // メニュー2：管理者用
  const adminMenu = ui.createMenu('⚙️ 管理者メニュー');

  adminMenu
    .addItem('✅ 完了承認・差し戻し', 'showApprovalDialog')
    .addItem('📊 AIサマリー', 'showAiSummaryDialog')
    .addSeparator()
    .addItem('👤 担当者設定', 'showMemberSettingsDialog')
    .addItem('⏰ リマインド設定', 'showReminderSettingsDialog')
    .addItem('📅 棚卸し設定', 'showReviewSettingsDialog')
    .addItem('🤖 AIモデル設定', 'showAiModelSettingsDialog')
    .addSeparator()
    .addItem('🔧 テンプレート初期設定', 'initializeTemplate')
    .addToUi();
}
```

### 状態遷移

```
                  担当者          担当者            管理者
  未着手 ──────→ 進行中 ──────→ 完了報告済み ──────→ 完了
                                     │
                                     │ 管理者
                                     ↓
                                  差し戻し ──→ 進行中（ループ）

  ※ どの状態からでも → 保留 にできる（管理者のみ）
```

**ルール：**
- 担当者ができること：未着手→進行中、進行中→完了報告済み
- 管理者ができること：完了報告済み→完了（承認）、完了報告済み→差し戻し、任意→保留
- 担当者は「完了」にできない。必ず管理者の承認が必要
- ログイン機能はない。ダイアログで「自分」を選ぶ運用（社内ツールのため）

## GASファイル構成

```
docs/gas/task-management/
├── taskMain.js              ← メニュー登録・エントリーポイント
├── taskCommonStyles.js      ← UI共通スタイル（既存パターン踏襲）
├── taskInputDialog.js       ← 画面1：モード選択 + テキスト入力
├── taskAiAnalyzer.js        ← AI呼び出し（Gemini API）+ プロンプト
├── taskResultDialog.js      ← 画面2〜4：候補選択 → 要件確認 → 登録
├── taskListDialog.js        ← 画面5：タスク一覧 + AIサマリー
├── taskSheetManager.js      ← スプレッドシート読み書き

```

| taskReminder.js | ~100行 | 毎朝トリガー、メール通知 |
| taskDiscussionPatterns.js | ~100行 | タスク種類別の質問パターン定義 |

合計：約1,600行

### システム vs AI の役割分担

| 機能 | システム（GAS） | AI（Gemini） |
|------|---------------|-------------|
| タスク候補抽出 | | ✅ |
| 確信度判定 | | ✅ |
| 曖昧表現検出 | | ✅ |
| 要件定義アシスト | | ✅ |
| ディスカッション質問生成 | | ✅ |
| AIサマリー | | ✅（ボタン押下時のみ） |
| スプレッドシート読み書き | ✅ | |
| カレンダー登録 | ✅ | |
| リマインドメール送信 | ✅ | |
| タスク一覧表示・フィルタ | ✅ | |
| 期限の色分け（🔴🟡⬜） | ✅ | |
| 担当者別グルーピング | ✅ | |
| 条件付き書式 | ✅ | |
| ID自動採番 | ✅ | |

**原則：確実に動く部分はシステム、柔軟な判断が必要な部分はAI。**
**AIが壊れてもシステム機能（一覧・登録・リマインド）は動き続ける。**

## 処理フロー詳細

### タスク登録フロー

```
1. ユーザー：メニューから「タスク登録」を選択
     ↓
2. taskMain.js：showTaskInputDialog() を呼ぶ
     ↓
3. taskInputDialog.js：画面1を表示
     ↓
4. ユーザー：モード選択 + テキスト貼り付け + 「AI解析する」クリック
     ↓
5. taskAiAnalyzer.js：
   - モードに応じたプロンプトを組み立て
   - Gemini API呼び出し
   - JSONパース
   - ログシートに原文+AI出力を保存
     ↓
6. taskResultDialog.js：画面2を表示（タスク候補一覧）
     ↓
7. ユーザー：✅ / ⬜ 選択 + 「要件を確認する」クリック
     ↓
8. taskResultDialog.js：画面3を表示（要件確認）
   - ✅にしたタスクを順番に表示
   - AIが埋めた部分は表示、不足部分は入力欄
     ↓
9. ユーザー：不足情報を入力 + 「登録」クリック
     ↓
10. taskSheetManager.js：
    - タスク一覧シートに行追加
    - ID自動採番（T-001形式）
      ↓
11. taskCalendarManager.js：
    - 期限がある場合、Googleカレンダーにイベント作成
    - 前日・当日リマインド設定
      ↓
12. taskResultDialog.js：画面4を表示（登録完了）
```

### カレンダー登録（要件を備考に保存）

タスク登録時にGoogleカレンダーのイベントを自動作成。
**備考（description）に要件全文を保存**することで、
スマホのカレンダー通知タップ → 要件がそのまま見える。

```
タイトル：📋 T-043 商工会議所折り込み発注
種類：終日イベント（期限日）
リマインド：前日9:00 + 当日9:00

備考（description）：
━━━━━━━━━━━━━━━━━━
担当：清水
状態：未着手

【完了条件】
両商工会議所に発注完了 + 搬入日程確定

【やること】
・小牧（33,000円・3,000部）の発注手続き
・春日井（55,000円・4,500部）の発注手続き
・印刷物搬入手配

【やらないこと】
・印刷物のデザイン変更

登録日：2026-03-11
━━━━━━━━━━━━━━━━━━
```

担当者がやること：
- スマホにカレンダー通知が来る
- タップすると要件が全部見える
- スプレッドシートを開く必要なし

### リマインドフロー

カレンダー通知が実質リマインドを兼ねる。
追加でメール通知も送る（カレンダーを見ない人向けのフォールバック）。

```
設定シートの「リマインド時間」に従ってGAS時限トリガーが実行
（デフォルト：毎日9:00、設定で変更可能・複数回設定可能）
  ↓
taskReminder.js：
  1. 設定シートからリマインド設定を読み取り
  2. タスク一覧シートを走査
  3. 期限が「今日」「明日」「超過」のタスクを抽出
  4. 担当者ごとにグルーピング
  5. 設定シートからメールアドレスを取得
  6. メール送信

週次棚卸しサマリー（設定シートの曜日・時間に従う）：
  デフォルト：月曜 08:30
  → 全未完了タスクの一覧 + 担当者別件数 + 超過件数
  → 管理者全員にメール送信

メール例：
━━━━━━━━━━━━━━━━━
📋 タスクリマインド（3/11）

🔴 期限超過（1件）
  T-038 資料修正（期限：3/8）

🟡 本日期限（2件）
  T-041 バナー作成
  T-042 確認ドキュメント送付

🟢 明日期限（1件）
  T-043 商工会議所折り込み発注
━━━━━━━━━━━━━━━━━
```

### 完了報告フロー（担当者）

```
1. タスク一覧ダイアログでタスクをクリック → 要件展開
2. 完了条件を確認
3. 「📝 完了報告」をクリック
4. 完了報告コメントを入力（任意）
   例：「両方発注済み。搬入は3/19に確定」
5. 「報告する」をクリック
     ↓
6. taskSheetManager.js：
   - 状態を「完了報告済み」に更新
   - I列（完了報告コメント）に入力内容を保存
     ↓
7. 管理者全員にメール通知：
   「T-043（商工会議所折り込み発注）が完了報告されました。
    担当：清水
    コメント：両方発注済み。搬入は3/19に確定
    完了条件：両商工会議所に発注完了 + 搬入日程確定
    → スプレッドシートを開いて確認してください」
```

### 完了承認フロー（管理者）

```
1. メール通知 or タスク一覧で「完了報告済み」のタスクを確認
2. タスクをクリック → 要件 + 完了報告コメントが表示される
3. 完了条件と照合して判断

【承認する場合】
4a. 「✅ 承認」をクリック
      ↓
    - 状態を「完了」に更新
    - J列に「承認者名 + 日時」を記録
    - カレンダーイベントを更新（タイトルに ✅ 追加）
    - 担当者にメール通知：「T-043が承認されました」

【差し戻す場合】
4b. 「↩️ 差し戻し」をクリック
      ↓
    差し戻し理由を入力：
    「搬入日の確認書を添付してください」
      ↓
    - 状態を「差し戻し」に更新
    - J列に「差し戻し理由」を記録
    - 担当者にメール通知：
      「T-043が差し戻されました。
       理由：搬入日の確認書を添付してください」
      ↓
    担当者が対応後、再度「完了報告」→ ループ
```

### 進捗確認フロー

```
【毎朝（自動）】
  リマインドメール + カレンダー通知
  → 超過・本日・明日のタスクが担当者に届く

【随時（手動）】
  メニュー → タスク一覧
  → 担当者別にフィルタして誰が何件持っているか確認
  → 🔴超過 🟡本日 🔵完了報告待ち がひと目でわかる
  → クリックで要件詳細を確認

【週次（月曜ミーティング）】
  タスク一覧を画面共有
  → 全タスクを上から確認
  → 超過・完了報告済み（未承認）を重点チェック
  → AIサマリーで全体傾向を把握
```

### Claude Code連携フロー

```
画面4で「Claude Codeで作業開始」をクリック
  ↓
要件情報をプロンプト形式に整形：

  以下のタスクの作業を開始してください。

  【タスク】コベルク提案資料修正
  【担当】渡邉
  【期限】3/20
  【完了条件】修正済み資料を担当者に共有し決裁取得
  【やること】
  - 商談メモの内容を資料に反映
  - 対象工場・対象者の情報を追記
  【やらないこと】
  - 教材制作
  - 導入後の研修実施

  ↓
クリップボードにコピー
  ↓
ユーザーがClaude Codeに貼り付けて作業開始
```

## テンプレート初期設定

1. **タスク一覧シート**：ヘッダー行 + 条件付き書式 + ドロップダウン

## 使い方（ユーザー向け）

### 初回セットアップ

```
1. GASエディタにコードを貼り付け
2. 管理者メニュー → テンプレート初期設定
3. 管理者メニュー → 担当者設定（ダイアログで登録）
4. 管理者メニュー → リマインド設定（時間・回数を設定）
5. 管理者メニュー → 棚卸し設定（曜日・時間を設定）
```

### 日常の使い方（担当者）

```
【タスク登録】
  📋 タスク管理 → タスク登録 → モードを選ぶ → テキスト貼る → AI解析 → ✅選択 → 登録

【作業開始】
  カレンダー通知 or タスク一覧で要件を確認 → 作業

【完了報告】
  📋 タスク管理 → 完了報告 → タスク選択 → コメント入力 → 報告
  → 管理者に通知が届く

【毎朝】
  カレンダー通知 + リマインドメールで期限確認
```

### 日常の使い方（管理者）

```
【完了承認】
  ⚙️ 管理者メニュー → 完了承認・差し戻し
  → 完了報告済みのタスク一覧 → 要件と照合 → 承認 or 差し戻し

【進捗確認】
  📋 タスク管理 → タスク一覧 → 担当者別にフィルタ
  → 超過🔴・本日🟡・報告待ち🔵 をチェック

【週次棚卸し】
  棚卸しサマリーメールが届く → タスク一覧を画面共有で確認
  → AIサマリーで全体傾向を把握

【設定変更】
  ⚙️ 管理者メニュー → 各設定ダイアログで変更
```
